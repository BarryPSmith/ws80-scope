# ws80-scope
Desktop software to visualise and store ws80 waveforms and test algorithms

# Building and Running
I use Visual Studio 2022 to build and run this software

# Connecting to hardware
Using the firmware supplied in https://github.com/BarryPSmith/ws80-alt-firmware, compile with debugging enabled (```make DEBUG=1```) and upload to the WS80. Exit DFU mode, then the device should show up as a USB serial port. Select that port in the dropdown menu, and it should start collecting and showing the data.

# Live behaviour
The program shows the most recent data frames it has received from the hardware. It shows:
 - The raw waveforms from each of the 12 channels, grouped into the 6 sensor pairs.
    + Press "Zoom" to show zoomed data to the period when the received waveform is strongest. This only matters if the firmware is compiled without ``DELAYED_ADC`` defined; by default that is defined and the hardware only captures the period of interest anyway.
    + Press "FFT" to view the FFT of the waveform instead of the time domain.
 - Numerical values, such as the calculated windspeed, direction, calculation residual, time of the frame and interval to create it, average windspeed & direction (along with values it retrieves from my webserver for the spinning cup values, for comparison).
 - A visualisation showing:
    + Lines of ideal fit for each of the 6 seonsor pairs (each sensor pair has a particular colour)
    + Instantaneous calculated best fit wind vector (black dot)
    + Average wind vector (red dot)
    + Comparison wind vector from my comparison station (green dot), retrieved from my webserver
 - The averaging period for reporting averages is adjustable by changing the value in the "Avg Period" textbox.

# Data Storage
This program automatically stores all frames it receives into a SQLite database called data.sqlite, in the current directory. 

This consumes a decent amount of disk space: the effecive bit rate when performing continous sampling comes out around 700 kbit/sec.

In addition to the raw frames, the database also stores metadata to separate the raw data into usable chunks. These are calibrations and sessions.

## Calibrations
Calibrations are periods when the sensor has been covered to ensure it has as close to zero wind as practicable. They are created by checking the "calibrate" checkbox. It is recommended to gather a large enough period of calibration data that random fluctuations are minimised. To finish a calibration, uncheck the calibration checkbox. At that time, the calibration data will be loaded into the wind calculators.

Calibration data is only persisted until the software is shut down. On startup, it is again uncalibrated. Calibration data can be recalled by clicking "Load Calibration" and choosing a calibration to load.

## Sessions
Sessions are simple a named time range over which data is gathered. To create a session, type a name into the "Current Session" textbox. A session is finished either automatically when the text of the "Current Session" textbox chages or the program is shutdown, or manually by clicking "Finish Session".

A session can be reloaded by clicking "Load Session". Then a particular time in a session can be chosen by moving the slider. When a time is selected, the last few frames before that time are replayed into the calculation engine so that it can show appropriate averages, etc.

Note that you technically don't have to use the sessions, it's possible to manually enter a start and end time on either side of the slider. That's quite an unfriendly thing to do though, the sessions are much easier (this should probably be removed, see section below on code quality).

### Reports
A CSV dump of the data can be generated for the current session by pressing "Generate Report". For each frame, this has a bunch of outputs from the calculation engine. It has calculated wind speed (according to either the short axes, long axes, or combined), and real and imaginary magnitude of the key frequency bins of each channel (from which phase, etc. can be calculated). It also contains comparison data retrieved for the comparison station, and data from the GPX file if loaded.

"Load GPX" is intended for cases where the data was generated by attaching the station to a moving vehicle. Honestly, the GPX data was so low resolution in my test data that I didn't really use it.

# Wind Algorithm Difference
It should be noted that this software doesn't use exactly the same algorithm as is used in the firmware. This software uses a FFT to calculate the phase / time shift; the firmware does a raw multiply with sine and cosine waveforms. I expect both methods to give very similar results, but haven't verified that.

# A note on code quality, and contributing
This was created as a rough and ready test environment for my development of the ws80-alt-firmware. The UI is not very thought through, I put in functions and visualisations as and when I need them. There are limited options on how data is stored and retrieved because I haven't needed anything more complex yet. The ability to get comparison data is hardcoded to get the comparison information from a particular station on my website. Some aspects, like the edge detection method of calculating wind, don't work anymore and should be removed. Some functions were put in as once off test cases, or because I needed a particular piece of data (particularly OnceOff.cs, but also in some other parts of the code.)

Anyone is of course welcome to make any changes they like to a fork of this. If you want to merge them back into this repo, or want my opinion on matters, please open an issue or contact me first. I would like a chance to clean things up and make some coding standards before collaborating!
